## Bloco 2 — Validação de Dados (Pydantic)

### Objetivo
Substituir dicionários soltos por schemas Pydantic rigorosos. Nenhuma validação manual com `if`.

### [ ] Exercício 2.1 — Schema de criação de sensor
- **Rota:** `POST /sensores`
- **Regras:**
  - `nome`: string, mínimo 3 caracteres, máximo 100
  - `tipo`: string, deve ser um de `["temperatura", "pressao", "vibracao", "humidade"]`
  - `localizacao`: string, mínimo 3 caracteres, máximo 150
- **Status:** `201 Created` | `422 Unprocessable Entity`

### [ ] Exercício 2.2 — Schema de resposta de sensor
- **Rota:** `GET /sensores/{id}`
- **Resposta:**
```json
{ "id": 1, "nome": "...", "tipo": "...", "localizacao": "...", "criado_em": "2026-09-28T10:00:00" }
```
- **Regra:** `criado_em` é um datetime gerado automaticamente no momento da criação.

### [x] Exercício 2.3 — Schema de criação de leitura
- **Rota:** `POST /sensores/{id}/leituras`
- **Body:**
```json
{ "valor": 72.5, "unidade": "C" }
```
- **Regras:**
  - `valor`: float, obrigatório
  - `unidade`: string, máximo 10 caracteres
- **Status:** `201 Created` | `422` | `404` se sensor não existe

### [ ] Exercício 2.4 — Schema de resposta de leitura
- **Rota:** `GET /sensores/{id}/leituras`
- **Resposta:**
```json
[
  { "id": 1, "sensor_id": 1, "valor": 72.5, "unidade": "C", "timestamp": "2026-09-28T10:05:00" }
]
```
- **Status:** `200 OK` | `404` se sensor não existe

## Bloco 3 — Ligação ao PostgreSQL

### Objetivo
Criar a base de dados, tabelas e conectar o FastAPI ao PostgreSQL com SQLAlchemy.

### [x] Exercício 3.1 — Configuração da base de dados
- **Tecnologia:** SQLAlchemy + psycopg2
- **Tabelas:**
  - `sensores`: id (PK), nome, tipo, localizacao, criado_em
  - `leituras`: id (PK), sensor_id (FK), valor, unidade, timestamp
- **Regras:**
  - `sensor_id` em `leituras` tem `ON DELETE CASCADE`
  - `criado_em` e `timestamp` são `DateTime` com default `datetime.utcnow`

### [x] Exercício 3.2 — Session management
- **Objetivo:** Criar uma dependência FastAPI que abre e fecha a session por request.
- **Regra:** Nunca uses sessões globais. Cada request tem a sua sessão.

### [ ] Exercício 3.3 — Refactor do Bloco 1 para PostgreSQL
- **Rotas afetadas:** todas as do Bloco 1
- **Regras:**
  - Trocar listas em memória por queries SQLAlchemy
  - Manter os mesmos status codes e formatos de resposta
  - O `id` passa a ser gerado pela base de dados
